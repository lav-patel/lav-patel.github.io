# lavpatel.com

Statically exported Next.js 14 site showcasing Lav Patel’s profile. The app router, Tailwind CSS, and shadcn/ui components deliver a single-page portfolio that can run on Vercel or GitHub Pages.

## Project Overview
- `app/layout.tsx` defines global metadata and wraps the app with the Inter font from `next/font/google`.
- `app/page.tsx` renders the home route and delegates all UI to `components/component.tsx`, keeping routing logic slim.
- `components/component.tsx` contains the entire landing page: sticky header, hero, about, resume CTA, and work experience fed by a local `experiences` array. It embeds `<Head>` metadata, JSON-LD schema, and social sharing tags so the static export keeps rich SEO.
- `components/AnimatedButton.tsx` is a client component that enhances CTA links with Framer Motion hover/tap animation.
- `components/ui/*` holds shadcn/ui primitives (Radix-based React components) used across the design system; they expect Tailwind classes and the `cn` utility.
- `lib/utils.ts` exposes `cn(...)`, a Tailwind-safe class name merger reused by UI primitives.
- `public/` serves profile imagery (`lav-patel.jpeg`), favicons, and sitemap artifacts generated by `next-sitemap`.
- `next.config.mjs` sets `output: "export"` and `images.unoptimized` so `npm run build` writes a static `out/` folder suited for GitHub Pages. `next-sitemap.config.js` mirrors the production domain for sitemap generation.

## Running & Deployment

```bash
npm install
npm run dev     # local development on http://localhost:3000
npm run build   # static build; outputs ./out and runs next-sitemap
npm run static  # build + sitemap + GitHub Pages extras + creates out.zip
```

Because the build is static, confirm external assets (e.g., profile image hosted at `https://lavpatel.com/lav-patel.jpeg`) stay reachable when deploying to a different domain.

## Content & SEO Details
- Hero imagery and copy live directly inside `components/component.tsx`. Update the inline `experiences` array to change the work history cards.
- The same file seeds structured data (`Person`, `WebSite`, `ItemList`) and social preview tags through `<Head>` and inline `<script type="application/ld+json">` blocks. Any schema updates must stay valid JSON.
- Canonical URL, resume link, and contact mailto are hard-coded; adjust them together to avoid stale SEO references.
- `public/robots.txt` and the generated `public/sitemap*.xml` assume the production hostname `https://lavpatel.com`. Regenerate with `npm run build` if the domain changes.

## Styling System
- Tailwind tokens are defined in `app/globals.css` and mirrored in `tailwind.config.ts`. Use semantic CSS variables (`--background`, `--primary`, etc.) to stay aligned with dark-mode support.
- shadcn/ui components consume Tailwind variants—prefer composing new UI from `components/ui` primitives instead of bespoke HTML so theme updates propagate consistently.
- `AnimatedButton` accepts `href` and `className`; extend button styles by passing Tailwind classes rather than editing the component.

## AI-Assisted Development Tips
1. Treat `components/component.tsx` as the canonical content map. When prompting an AI assistant, specify the section name (“hero header”, “About Lav Patel copy”, “Work Experience cards”) to keep edits localized.
2. For new sections, consider extracting reusable pieces into smaller components under `components/` to prevent the main file from growing past readability limits. Mention the desired insertion point (e.g., “between the About and Resume sections”) so automated edits respect layout flow.
3. When adding UI, reuse shadcn primitives (`Card`, `Accordion`, `Tabs`, etc.) and import from `@/components/ui/<name>`; remind the AI to import `cn` if conditional classes are needed.
4. Reference the Tailwind design tokens instead of raw hex values to preserve dark-mode behavior. Call out whether a component must support `className` overrides.
5. Before requesting documentation updates, note that README content should mirror any new links, metadata, or data structures (e.g., if you add a `projects` array, document its schema here).
